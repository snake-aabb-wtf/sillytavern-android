# 设备验收清单（SillyTavern Sol 1.0）

本清单对应设计文档 §7 的七项设备验收，用于在真机上确认 v1 可用。
每一项都给出操作步骤、期望结果和失败时的排查入口。

> 验收在真机执行；本仓库的 CI 只证明能编译、能启动 Node 18 冒烟，不代替以下检查。
>
> **状态：2026-11-03 已在真机执行，七项全部通过**（用户确认；机型与系统版本待补）。

## 安装

- **产物**：GitHub Releases 中 `st-sol-*` 标签附带的 `app-debug.apk`（debug 签名）。
- **架构**：仅 `arm64-v8a`。x86_64 模拟器镜像无法安装；请用 arm64 真机或 arm64 模拟器。
- **系统版本**：Android 8.0（API 26）及以上。
- **体积**：APK 约 **202 MiB**。安装与首次启动还需要额外的解压空间，建议设备至少留出 **1.5 GB** 可用空间。
- **安装权限**：通过浏览器/文件管理器打开 APK 时，按提示到「设置 → 应用 → 特殊权限 → 安装未知应用」为本来源授权。
- **覆盖安装**：后续构建使用同一 debug 签名，可直接覆盖安装；`data/` 不会被清空。
- **首次启动**：需要把 APK 内约 152 MB 的 `runtime.zip`（服务端 + 生产依赖 + 预编译前端库）解压到应用私有目录，通常 **30–120 秒**，低端机更久。期间停在「正在准备运行环境…」并显示进度条，**不要划掉应用**；解压只发生一次（版本未变时直接复用）。
- **日志位置**：应用私有目录 `filesDir/logs/node.log`。入口：主界面右上角齿轮 →「设置」→「查看日志」；启动失败页也有「查看日志」。日志页提供「分享」（系统分享面板）和「导出」（保存到 Download 等位置）。
- **导入生效**：数据导入只是暂存，**必须重启一次应用**（从最近任务中划掉再打开）才会替换当前数据。若应用检测到 Node 线程仍在运行（例如上次启动超时），会提示「导入已暂存：服务仍在运行，请重启应用后完成导入」，此时导入标记保留到下次冷启动，不要反复点「重试」。

## 验收项

### 1. 首装启动，进度条走完进界面

**操作步骤**

1. 在受支持的真机上安装 APK。
2. 首次打开应用，观察启动页文案与进度条。
3. 等待进入 SillyTavern 主界面。

**期望结果**

- 启动页依次显示「正在准备运行环境…」→「正在启动 SillyTavern…」→「正在加载界面…」。
- 首次准备环境耗时数十秒到两分钟，进度条持续推进，不闪退。
- 最终显示 SillyTavern 聊天界面（不是空白页或错误页）。
- 通知栏出现「SillyTavern 正在运行」的常驻通知。

**失败时看哪里**

- 启动失败页点「查看日志」，或 设置 →「查看日志」。
- 重点看 `node.log` 末尾：解压错误（`RuntimeInstaller`）、`node::Start` 失败、端口未监听、`EACCES`。
- 若日志文件不存在，说明服务尚未启动过；先点「重试」。

### 2. 新建角色、导入 PNG 角色卡

**操作步骤**

1. 在 SillyTavern 界面打开角色管理（右侧人物图标）。
2. 新建一个角色，填写名称与描述并保存。
3. 用「导入角色」选择一个 PNG 角色卡（V2 内嵌 JSON 的 PNG）。
4. 刷新角色列表。

**期望结果**

- 新角色出现在列表中，可打开其聊天。
- PNG 导入后角色出现在列表，头像与名称正确。
- 全程无崩溃；导入后列表立即刷新。

**失败时看哪里**

- 设置 →「查看日志」；导入相关错误会在 `node.log` 中出现（文件读取、解析失败）。
- 若文件选择器没有打开或选完无反应，记录机型与文件管理器，并在日志里找 `file chooser` / `STBridge` 相关行。

### 3. 配一个 API，发一条消息，收到回复

**操作步骤**

1. 打开「API 连接」设置（插头图标）。
2. 选择一种聊天补全来源（如 OpenAI 兼容 / Custom），填入 Base URL、API Key 与模型名。
3. 保存并连接。
4. 在任意角色聊天中发送一条短消息。

**期望结果**

- 连接测试/模型列表可用，设置保存后不丢失。
- 消息发送后显示「正在输入」，随后收到模型回复并写入聊天记录。
- 若网络不可达或 Key 错误，界面显示可读的错误提示，应用不崩溃。

**失败时看哪里**

- 设置 →「查看日志」：`node.log` 中会有请求失败、超时或 4xx/5xx 记录。
- 确认手机网络可访问所填 Base URL；应用只把本地服务限制在 127.0.0.1，出站请求不受影响。

### 4. 杀进程重开，角色与聊天记录都在

**操作步骤**

1. 在验收项 2、3 之后，从最近任务中划掉应用（或系统设置里强行停止）。
2. 重新打开应用。
3. 打开角色列表与之前的聊天。

**期望结果**

- 应用重新启动并进入界面（无需重新解压，启动明显更快）。
- 新建的角色、导入的 PNG 角色卡、聊天记录与 API 设置全部还在。
- 常驻通知重新出现。

**失败时看哪里**

- 设置 →「查看日志」，确认服务正常启动且 `data/` 路径可写。
- 检查是否使用了「清除数据/清除存储」，这会删除 `filesDir` 下的全部内容。
- 划掉应用会结束进程（这是当前的停止方式），已落盘的聊天记录不受影响；正在生成中的回复可能丢失。

### 5. 导出数据到 Download，再导入回来

**操作步骤**

1. 主界面齿轮 →「设置」→「数据备份」。
2. 点「导出数据」，在系统保存面板选择 Download 目录，文件名保留 `.zip`。
3. 导出完成后，在文件管理器确认 zip 存在且大小合理。
4. 回到应用，点「导入数据」，选择刚才的 zip，确认覆盖提示。
5. 按提示从最近任务中划掉应用，再重新打开。
6. 检查角色、聊天记录与设置是否恢复。

**期望结果**

- 导出成功提示「已导出 N 个文件（大小）」，Download 中出现 zip。
- 导入阶段提示「导入已准备好，重启应用后生效」。
- 重启后数据与导出时一致；之前的临时数据被替换，没有重复条目错误。
- 如果导入包损坏或缺少 `default-user/settings.json`，界面给出明确错误，现有数据不被破坏。

**失败时看哪里**

- 设置 →「查看日志」：`DataBackup` 相关行（导出/暂存/替换/恢复 config）。
- 导入后在启动阶段失败时，启动失败页会显示「导入数据应用失败：…」并保留 `data.old` 供排查。
- 若提示「请重启应用后完成导入」，说明替换被推迟（Node 线程仍存活）；从最近任务划掉应用再打开即可。
- 导出中断会删除半成品 zip；重新导出即可。

### 6. 后台放置 10 分钟，回前台仍可用

**操作步骤**

1. 进入任意角色聊天，按 Home 键把应用切到后台。
2. 保持后台 10 分钟（可锁屏），期间不要从最近任务划掉。
3. 回到应用，继续发一条消息。

**期望结果**

- 通知栏始终显示「SillyTavern 正在运行」。
- 回到前台时页面仍在原位置，无需重新加载或重新解压。
- 能立即发送消息并收到回复。

**失败时看哪里**

- 若回来变成启动页/重新加载，查看通知是否被系统移除；部分厂商的省电策略会杀后台，需在系统设置中允许自启动/后台运行。
- 设置 →「查看日志」看服务是否被重启（日志中出现新的启动段）。
- 注意：从最近任务划掉应用会主动结束进程，这是预期行为，不属于本项失败。

### 7. 扩展页：git 相关操作给出「Android 不支持」提示而不是崩溃

**操作步骤**

1. 打开「扩展」页面，确认已安装扩展列表正常显示。
2. 对任意已安装扩展点「更新」（或尝试切换分支）。
3. 可选：尝试用 Git URL 安装一个新扩展。

**期望结果**

- 扩展页可以正常打开和滚动，应用不崩溃。
- 更新/切换分支/读取版本这类依赖系统 git 的操作返回可读提示：「此操作需要系统 git，Android 版不支持」（HTTP 501），界面显示错误而不是无响应。由于 `/version` 也返回 501，扩展卡片不再显示 git 分支/提交信息，这是预期结果。
- 用 Git URL 安装扩展走应用内的纯 JS git 实现，预期可用；该路径尚未在真机上验证，若失败按已知问题记录。

**失败时看哪里**

- 设置 →「查看日志」：查找 `/api/extensions/update`、`/api/extensions/branches`、`/api/extensions/switch`、`/api/extensions/version` 的 501 记录，或 `/install` 的 git 错误。
- 若整个扩展页白屏，先确认第 1 项主界面正常，再看 `node.log` 是否有未捕获异常。
